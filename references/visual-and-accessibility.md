# 视觉与可访问性

## 定位关系的拥有者

修正前分别看父级内边距、子控件尺寸、系统自带背景、图片透明边缘、字体基线与装饰层。不要用随机位移抵消结构问题。比较完整一行的边缘与行内字形中心，不把两种对齐混为一谈。

视觉图标可以小，操作区域仍需符合目标平台约定。移除灰底时检查原生控件底层是否仍存在；额外包一层透明材质不能消除原有底色。缩小间距不改变选择范围或点击回调。

## 字体与内容

沿用项目字族，原生优先尊重平台排版。字体大小、字重、行距和容器宽度一起建立层级。大标题可按实际字族微调字距，中文、小字和不同脚本分别判断。变量字体有相应轴才使用光学尺寸，不假定每个系统字体都支持同一设置。

原生检查 Dynamic Type 或相应平台设置；Web 检查缩放、重排和相对字号。大字号下允许控件增高和合理换行，主要动作、错误及关键数据不可被截断。长数字、货币、日期和本地化字符串使用真实的压力内容。

## 材质的任务

实色、半透明和阴影都可以建立层级。选择时看背景的复杂程度、滚动关系、文字对比及设备开销。大面积正文宜保持稳定可读，半透明工具栏需要在实际背景上测试。

模态流程需要相应焦点管理、退出途径和背景交互隔离；是否使用遮罩由语义与平台决定。并排工作的面板不应无故阻断主内容。不要仅凭外观把一个普通侧栏标成 `aria-modal`。

Web 使用 `backdrop-filter` 时提供无支持的实色回退。减少透明度、更多对比和强制颜色模式按支持情况增强，但默认样式本身也要可读。不能仅依赖某个媒体查询一定存在。

## 输入与可访问性

- 原生语义优先；Web 的可点击动作使用按钮，导航使用链接。确保键盘可达、可操作且焦点可见。
- 模态打开后焦点进入合适位置，关闭后回到合理来源；Escape、返回和系统手势遵循平台。避免键盘陷阱。
- 减少动态效果时保留任务结果和反馈，移除不必要位移、视差和回弹。不要只在视觉层强制 `transform: none`，却让手势逻辑仍依赖变换位置。
- 状态不能只靠颜色表达。错误、选中、禁用在高对比环境和辅助功能树中仍有明确语义。
- 装饰不应抢焦点；图标独立承担动作时有可访问名称。布局变更后检查阅读和焦点顺序。

可访问性验收按变化选取：布局和重排看实际页面；焦点和交互用键盘；名称与读出语义用辅助功能检查或读屏。不存在一个截图能证明所有项目的通过。
