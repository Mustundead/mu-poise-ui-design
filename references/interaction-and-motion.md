# 交互与动效

先用平台已有控件和项目已有动画系统。以下是跨平台判断，Web 实现要额外遵守指针、滚动、焦点和浏览器默认行为。

## 建立清楚的状态

可拖动组件至少区分 `idle → pressed → dragging → settling → idle`。`pressed` 阶段可能是点击或滚动；不应立刻阻止两者。取消、失去捕获、页面失去焦点、组件移除都需要结束追踪并恢复合法状态。一次交互只处理已确认的主指针，额外指针不能覆盖已有手势。

在 Web 上：

- 接收 `pointerdown` 后保存指针身份、抓取偏移和当前位置；使用 Pointer Capture 时处理 `pointercancel` 和 `lostpointercapture`。
- `touch-action` 根据确实需要的手势方向设置，并在手势开始前生效。垂直页面中的水平控件应保留可用的页面滚动；不要给整页设为 `none`。
- 用小幅位移及方向证据判断意图，阈值依设备和现有组件而定，不把固定像素数当标准。边缘和滚动容器嵌套时实际操作验证。
- 点击语义优先交给原生按钮。拖动开始后避免误触点击，取消后不得执行提交。提供按钮、键盘或其他非拖拽的完成路径。

## 从当前位置接续

动画目标是逻辑状态，屏幕上的位置是当前呈现状态，两者在运动中不同。重新拖动时，从当前呈现位置接管，再计算指针相对偏移。优先使用动画库的连续值，不混用布局坐标与变换后的坐标。

用近期带时间戳的样本估计释放速度，统一为组件坐标中的距离/秒。只保留很短的窗口，避免长时间停住后仍用早前的速度。重复时间戳、低采样、快速反向和取消要有有限值处理；暂停后恢复动画不能带着异常大的时间步长跳走。

重定向时尽量保持位置和速度连续；是否把释放速度传给动画由 API 能力决定。查清速度是绝对单位还是按剩余距离归一化。后者在距离接近零时要避免除零。CSS transition 可以自然重定向某些简单属性，不能据此宣称所有 CSS 动画都不可中断。

## 松开后去哪儿

合法落点来自产品规则：关闭、半开、展开，或离散卡片位置。投影只辅助判断意图，最终目标仍需限制在允许范围内。确认当前位置、速度符号、方向及取消策略一起参与决策；不要仅凭速度或仅凭距离决定所有交互。

可使用简单的 `预计位置 = 当前位置 + 释放速度 × 预测时间` 作原型。预测时间是本地调参，不是 Apple 常量。这个模型不等同于真实滚动减速；长列表优先使用平台滚动而不是模拟惯性。需要更真实投影时沿用成熟组件并核对当前版本的实现。

边界可用逐渐加大的阻力帮助表达范围，但不可掩盖非法状态。松开后回到合法位置；减少动态效果时也应完成正确落点。弹性幅度、运动距离和目标尺寸要一起判断。

## 弹簧和时间

`mass / stiffness / damping`、阻尼比、`response`、`duration / bounce` 是不同 API 语义。不要直接复制数字或把 `damping: 1` 宣称为通用临界阻尼。先验证所用库的单位、速度继承、重定向和终止条件。

MU LABS 的默认选择是收敛、克制、不影响输入。是否有回弹由手势和产品语义决定，没有统一时长。两轴运动可以独立控制，但有关联的几何关系仍需共同约束。

## 性能与反馈

Web 的持续更新使用项目已有渲染管线或 `requestAnimationFrame`。减少逐帧读写布局的交错；优先验证 transform/opacity 路径，但不要宣称它们在所有内容上都免费。`will-change` 按需启用，避免长期占用大量图层。

不要默认逐帧动画 blur、阴影或全屏滤镜。用性能记录确认问题，再优化实际瓶颈。音效和触觉仅用于有意义的事件，遵循设置与平台能力；Web Vibration 不是跨浏览器可靠的触觉接口，不承诺画面、声音和触觉必然同帧。

手势核心验收：按下反馈、抓取偏移、拖动连续性、滚动共存、快速反向、松开落点、取消、重复操作和键盘等价路径。只测本次相关项。
