# 维护者行为评估

维护时使用；不把这些题目变成日常小修的必做流程。[evaluation-cases.md](evaluation-cases.md) 只放可交给执行者的题目，本页的判据与修改意图留给维护者。

## 重跑

1. 固定请求、截图/当前运行画面、设计变量、平台与版本；如涉及手势，再给状态代码和可复现操作。保存输入摘要。只有数字或旧截图时，不补造当前视觉证据。
2. 用相同输入在新的上下文分别执行旧包和候选包。保持模型请求、工具可用性和评审/实现权限一致；记录实际暴露的模型身份，未暴露就记未确认。
3. 原样保存输出及读取文件、实际看过的图、使用工具和限制。执行者只见题目及原始材料，不见判据、旧答案和升级诊断。
4. 独立检查最重要的发现是否对应可见现象、影响、规格确定方法与可验证动作。实现任务还要检查当前候选运行界面、受影响状态、交互和可访问性。原型或教学图不能冒充产品验收。
5. 记录收益、回归与证据缺口。只有新差异、失败或未解决风险才继续修改和重跑。

## 判据（维护者使用）

| 维护者行为等级 | 可观察证据 |
| --- | --- |
| 未达标 | 漏掉给定证据中妨碍主任务的明显问题、建议造成关键状态失真、把手势取消当提交，或无运行证据却宣称已验收。 |
| 基础可用 | 能指出明显缺陷，但只谈统一数字或装饰，未把主次、容器和任务关系说清。 |
| 专业成熟 | 区分基础正确和品质提升，优先抓住影响任务的关系；沿用设计变量并给尺寸确定方法，保留密集界面所需密度与现有交互。 |
| 精细打磨 | 在成熟基础上，有实现任务及相应环境时，前后画面、相关手势、语言/大字号与辅助技术证据支持结论，限制准确。 |

这是**技能执行者的行为等级**，不是页面交付等级；两者不能互相代替。将影响程度和证据可信度分开判断，不靠发现数量、关键词或主观分数。对只有实现代码的题，正确说出“无法判断精美”不能被判成能力不足。
